## What the completed runs show

Both current cStack modes passed all five separate bug graders. Every new trial
used one controller attempt. Multi-agent cStack used 3,291,046 tokens versus
773,930 for current single-agent cStack: 4.25 times as many. Its combined task time
was 575.3 seconds versus 329.0 seconds, approximately 75% longer. It used more
tokens and took longer on every one of the five paired cases, without adding a
private-test pass. These selected repairs support keeping the single-worker
plugin default. They do not establish whether helpers improve larger tasks or
find defects outside the benchmark checks.

Against the saved pstack multi-agent workflow, current cStack multi-agent used
54.3% fewer tokens. Its task time was 8.7% lower in these records; this small,
unrepeated cross-cohort timing difference does not establish a reliable speedup.
It used 9.8% more tokens and took 42.8% longer than saved plain Codex multi-agent.
It also used 60.4% more tokens than saved single-agent pstack. The multi-agent
cStack result therefore does not justify a broad claim that cStack beats every
pstack/plain configuration. Pstack here means the pinned skills adapted to Codex,
not the native Cursor/Claude plugin runtime.

The refreshed single-agent cStack total was 15.3% below saved plain Codex's token
total, while its task time was 14.2% longer. That is a descriptive comparison with
an earlier run, not proof that controller changes caused a token saving. The
original cStack 4/5 outcome and its pre-worker abort remain preserved separately.

## Evidence and human review

All ten new trials have complete native usage records: ten parents plus ten
helpers, GPT-6.1 Sol with medium reasoning, no nested delegation observed. Across
the old and new comparisons, 64 distinct native threads were reconciled without
duplicate identities. For every new trial, controller budget charges match the
final native parent/helper counters exactly. The earlier 25-trial result digest
remains unchanged.

The operator inspected all helper tool calls and the six commands flagged for
file writes. They create temporary regression reproductions; five explicitly
select `/tmp` and one uses Python's default temporary directory without a project
directory argument. No helper project-source patch was observed. Test commands
can create cache/build files. This trace review is not an OS read-only guarantee
and does not approve candidate test changes.

One candidate, single-agent Flask, reached `VERIFIED`. The other nine retain
`NEEDS_MANUAL_VERIFICATION` for existing test-file changes. All ten passed both
public probes and private bug grading. No human approval was fabricated.
