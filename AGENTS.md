# cStack contributor rules

- Implementation requests require real implementation, not an audit or plan as a substitute.
- No second coding agent unless explicitly authorised.
- Never claim VERIFIED without controller-owned, current acceptance evidence.
- Never alter or weaken acceptance oracles to obtain a pass.
- Prefer minimal dependencies and measurable correctness over sophisticated orchestration.
- Treat credentials, customer data and repository work as sensitive. Never add hidden network/billing fallbacks.
- Never push, merge, migrate, deploy or delete user work without permission.
- Maintain tests for false completion, no-op, tests-only patches, verifier failure, retry and resume.
